# 竞技场对战 · 机制说明（设计文档 §7.4）

> 实现文件：`src/battle.js`（引擎，纯函数）· `src/rivals.js`（内置对手）· `src/components/Battle.jsx`（UI）
> 自检：`npm run test:battle`（不依赖浏览器，覆盖属性表合法性、伤害不变量、战斗收敛、同种子复现）

## 0. 参考项目与借鉴边界

| 项目 | 借鉴了什么 | 协议 |
|---|---|---|
| [smogon/pokemon-showdown](https://github.com/smogon/pokemon-showdown) | 伤害公式（Gen5）、能力等级 −6..+6 分数表、先制度→速度的行动顺序、灼烧/麻痹/睡眠的处理方式、PP 与「挣扎」、STAB 与会心框架 | MIT |
| [@pkmn/sim](https://www.npmjs.com/package/@pkmn/sim) | 调研结论：曾评估直接引入，但其绑定官方 1000+ 种族/招式数据（数 MB），与「仓库精灵 + 自研六维」不匹配，最终只参考机制未引入代码 | MIT |
| 《赛尔号》(Seer) | 「克制 / 微弱 / 无效」三档克制呈现、以属性技能为核心的直球节奏 | 商业作品，仅玩法借鉴 |
| [patch-gg/pixelfx](https://github.com/patch-gg/pixelfx) | **攻击特效**：代码绘制的像素特效库（244 个特效、零图片素材、种子随机），直接按模块引入其 `fire / water / lightning / impacts / nature / explosions / projectiles / spawn` 特效贴到被打精灵身上；本项目只写选片与定位（`src/vfx.js`）。声明见 `THIRD-PARTY.md` | MIT |

**为什么没把引擎直接跑在浏览器里**：Showdown 是开源战斗模拟器里做得最好的（社区标准、MIT），我们也确实把它跑通了——把 9 属性表、自定义种族与招式灌进它的 Dex 后，它能按官方规则打完一整场。但作为**运行时**引擎代价太大：

- `@pkmn/sim` 解包 46MB（含 1–9 代全部图鉴数据），前端要懒加载一个数 MB 的 chunk，首屏和体积都不可接受
- 它的招式/种族 id 走 `toID()`，中文名会被压成空串，必须全量改成 ASCII id 再回映射中文
- 战斗输出是 `|move|` / `|-damage|` / `|split|` 协议流，UI、动画、中文战报、自动补位、经验结算都要重写

所以最终采用：**机制抄骨架（公式、顺序、状态机），数据自研；把官方引擎接进来做「标准答案」逐项对拍**。

## 1. 数值

- 战斗等级固定 **Lv.50**（等级不直接进伤害公式，仓库规模差异体现在六维里）
- **HP** = `60 + HP维 × 1.3`（HP 维 30 → 99，100 → 190）
- **伤害**（Showdown Gen5 公式）：
  ```
  base = floor(floor(floor(2×50/5+2) × 威力 × A / D) / 50) + 2
  最终 = base × STAB(1.5) × 克制倍率 × 会心(1.5) × 随机(0.85–1)
  ```
  物理技用 攻击/防御，特殊技用 特攻/特防；A/D 均乘能力等级系数
- **会心**：基础 1/16，重击技 1/8
- **灼烧** 攻击减半 + 回合末 1/16；**中毒** 回合末 1/8（草系特性减半）；**麻痹** 速度减半 + 25% 失手；**沉睡** 1–3 回合

## 5. 回合流程

1. 换人动作先结算（换上来的吃入场特性）
2. 技能按 **先制度 → 速度（含等级/麻痹/特性）→ 种子随机** 排序执行
3. 执行中若目标倒下，后续动作跳过
4. 回合末：异常伤害 → 特性回复 → 检查倒下 → 自动补位（无替补则分胜负）

对手 AI：每技能估 `伤害 × 命中率`，可斩杀 +600 权重，乘 0.9–1.1 噪声；血量 <30% 且替补属性更优时按难度概率换人（新手 15% / 相当 40% / 强敌 60%，新手另有 30% 随机技）。

## 6. 对手从哪来（三种挑战，v0.5）

竞技场开局先选挑战方式：

| 模式 | 对手来源 | 难度 | 人数 |
| --- | --- | --- | --- |
| **在线对手** | 输入对方 GitHub / Gitee 仓库，现场 `scanRepo()` 扫描 → `judge()` 生成（命中内置快照则离线直取） | 无（仓库真实数值，等级 / 品质 / 六维都是它自己的） | 1v1 |
| **同类型对战** | `sameTypePool()`：先发精灵主属性相同的仓库排前，副属性相同的补后 | ×0.65 / ×1 / ×1.35 | 1–3 对等 |
| **随机宠物** | `pickRandomTeam()`：36 只内置对手全体随机（Fisher–Yates + 显式种子） | ×0.65 / ×1 / ×1.35 | 1–3 对等 |

`src/rivals.js` 内置 36 个知名仓库的离线快照（React、Linux、Rust、PyTorch、Django、Kubernetes、Flutter、Laravel…每个元素至少 3 只），经同一套 `judge()` 判定引擎生成，因此对手和玩家的精灵在同一规则下诞生。同类型 / 随机模式先按玩家队伍等级中位数挑相近的对手，再把难度倍率实打实乘到六维与等级上（`scaleRival()`，六维夹在 6–150、等级夹在 1–999）；对手人数 = 玩家上场人数。

## 7. 与官方引擎对拍（不是"看起来像"）

`npm run test:parity` 会把同一套属性表与自定义种族/招式灌进 `@pkmn/sim`，让它打真实对局，再把相同输入喂给 `src/battle.js`，逐项比对：

```
克制表：81 组全部比对，差异 0 组
伤害样本：178 次（81 组属性对），超出官方区间的 0 次
与 Showdown 完全一致。
```

做法要点：两边都用 Lv.50、同六维（全 80）的标准种族，等级/能力值由 Showdown 实际算出后回填给我们的公式，因此比的是**公式本身**而不是数值设定。会心一击、免疫（雷→地 = 0）、克制与抵抗（×2 / ×0.5）都在样本里。

> `@pkmn/sim` 只在 `devDependencies` 里，只在自检脚本里用，不会打进前端产物。

## 8. 结算与成长

- EXP：新手 90 / 相当 150 / 强敌 240，胜 ×1.4、败 ×0.6，全队平分
- 羁绊：胜 +4 / 败 +1；累计 `battles / wins` 写入图鉴
- 引擎是纯函数 + 显式种子：同种子同操作序列必然复现（自检里有断言），这延续了 §2.2 的确定性原则

## 9. 攻击特效（pixelfx）

特效不手写、不画雪碧图：直接引入 [pixelfx](https://github.com/patch-gg/pixelfx)（MIT）的代码绘制像素特效——
每个特效是一小段程序（粒子 + 加色光照缓冲 + 种子随机），和 GitMon 的种子像素精灵是一个审美体系，且没有图片素材。

### 9.1 选片规则

`src/vfx.js` 为 9 个属性各配了四档特效，按技能威力选档（<55 轻击 / <80 主力 / <105 重击 / ≥105 终极）：

| 属性 | 轻击 | 主力 | 重击 | 终极 |
|---|---|---|---|---|
| 火 | fireball | flamethrower | fire-tornado | meteor |
| 水 | splash | water-orb | wave-crash | geyser |
| 雷 | zap-hit | spark-arc | ball-lightning | lightning-strike |
| 钢 | parry | bullet-impact | crit-hit | ground-slam |
| 地 | earth-spike | quake | ground-slam | dirt-explosion |
| 岩 | boulder | dirt-explosion | small-explosion | big-explosion |
| 风 | energy-disc | tornado | implosion | plasma-explosion |
| 草 | thorns | spore-burst | acid-splash | poison-cloud |
| 普通 | blunt-hit | hit-spark | crit-hit | cartoon-pow |

选片只挑「在原点炸开」型特效（跳过 pixelfx 里带龙套角色的 acted 特效），所以直接贴到被打精灵身上即可，不算弹道。

### 9.2 播放与节奏

- 事件重放：`Battle.jsx` 按 `battleTurn` 返回的事件序列定时重放——`move` → 出手前冲 + 在防守方身上播特效；`damage` → 白闪 + 后退 + 浮动伤害（会心追加整屏冲击帧）；`faint` → 烟尘散去；`switch` → 传送门登场。
- 时长封顶：pixelfx 部分特效长达 5–7 秒，按档位压到 1.1–2.2s（超长部分加速播放，最多 2.4×），战斗节奏不被特效拖住。
- 性能：特效模块单独拆包（`vfx-*.js`，gzip 约 94KB），进入竞技场才加载；每帧只在特效自己的小画布上做 `clearFrame → draw → composite → putImageData`。

> 许可证与引入方式见 `THIRD-PARTY.md`。
